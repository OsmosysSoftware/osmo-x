## Important Notes

### Package Names
Optimus UI v2 keeps the same public entry points and component APIs as v1, which was itself
API-compatible with PrimeNG v21. v2.0.0 exists because it moved to Angular 22, not because the
component API changed.

| PrimeNG | Optimus UI |
| --- | --- |
| `primeng` | `@openng/optimus-ui` |
| `primeicons` | `@openng/icons` |
| `@primeuix/themes` | `@openng/optimus-ui-themes` |
| `tailwindcss-primeui` | `@openng/optimus-ui-tailwindcss` |

Subpath suffixes are preserved: `primeng/button` becomes `@openng/optimus-ui/button`.

### Import Paths

```typescript
// Form inputs
import { Textarea } from '@openng/optimus-ui/textarea';  // NOT '.../inputtextarea'
import { InputText } from '@openng/optimus-ui/inputtext';
import { Select } from '@openng/optimus-ui/select';  // Previously 'dropdown'
import { Checkbox } from '@openng/optimus-ui/checkbox';

// Config and theming
import { provideOptimus, Optimus } from '@openng/optimus-ui/config';
import Aura from '@openng/optimus-ui-themes/aura';

// Always check the component documentation page for the correct import path
```

### Identifier Renames from PrimeNG
- `providePrimeNG` becomes `provideOptimus`
- `PrimeNG` (config class) becomes `Optimus`
- `PrimeNGConfigType` becomes `OptimusConfigType`
- `PrimeIcons` becomes `OpenngIcons` (the old name still compiles via a deprecated alias)

### What Did Not Change
- Component selectors keep the `p-` prefix (`p-button`, `p-table`)
- Icon classes keep the `pi-` prefix (`pi pi-search`)
- Design tokens keep the `--p-*` prefix
- Pass through (`pt`) and the `dt()` design token function work as before

### When Using Optimus UI Components
1. Always refer to the official documentation for import paths
2. Check the component's page for usage examples
3. Use WebFetch or Context7 to get latest component documentation
4. Optimus UI v2 requires Angular 22+ and RxJS 7.8.1+
5. There is no Optimus MCP server; fetch docs from https://optimus.openng.org
6. Optimus UI v2 exists but diverges from PrimeNG v21 - this project is pinned to v1
